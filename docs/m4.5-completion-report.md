## Design

No architectural change: Cloud is a configuration of the existing `HindsightMemoryService` (one bank per customer +
shared outcomes bank, durable M3 ledger, M4 unaffected).

* **Settings** (`app/config.py`): `HINDSIGHT_DEPLOYMENT` (`self_hosted` default | `cloud`),
  `HINDSIGHT_CLOUD_BASE_URL` (default `https://api.hindsight.vectorize.io`), `HINDSIGHT_API_KEY` (Cloud key),
  new `HINDSIGHT_SELF_HOSTED_API_KEY` (optional, self-hosted auth). `hindsight_effective_base_url` and
  `hindsight_client_key()` pick the URL and key for the selected deployment.
* **Key routing:** the Cloud key is sent only in cloud mode and only to the Cloud URL. The M1/M2 behaviour of sending
  `HINDSIGHT_API_KEY` to the local server was removed (the user's `.env` now holds a Cloud key). Also applied to the
  M1 spike and no-LLM check scripts.
* **Validation:** cloud mode requires an https URL (loopback allowed only for local fake servers) and rejects
  `HINDSIGHT_EXTRACTION_MODE` (undocumented for Cloud).
* **Missing key:** the app starts; memory reports `disabled` with the reason "HINDSIGHT_API_KEY is not set";
  interactions are saved and stay `disabled` in the ledger, synchronised automatically once a key is configured.
* **Errors:** 401 → `auth_failed`, 402 → `no_credits` ("credits exhausted: add credits, then retry"), 403 →
  `forbidden`. Fixed messages (no response body, no key), never retried automatically, visible in the ledger and
  retryable via `POST …/memory/writes/{id}/retry`. 429/502/503/504 and timeouts remain bounded transient retries.
* **Status:** in cloud mode `GET /api/system/memory` uses an authenticated one-item bank listing (the cheapest call;
  bank names discarded) instead of `/health`, and reports auth/credit/network problems.
* **Redaction:** `hsk_…` patterns are redacted in addition to the configured key.
* **Diagnostics:** retain/reflect results carry Hindsight's token `usage` (internal; used for cost estimates).

### Bugs found and fixed while testing

1. **Bank-creation errors were misclassified.** `create_bank` in the client calls aiohttp directly with
   `raise_for_status()`; our facade treated the resulting `ClientResponseError` as "unreachable", so a 401/402/403
   during a customer's first write would have been retried as transient. Now mapped to the real HTTP status.
2. **Timeouts ignored on low-level calls.** The generated APIs (list memories, get memory, delete document,
   observation history, health, bank listing) do not inherit the client timeout; a slow server could block for
   aiohttp's 5-minute default. `HINDSIGHT_TIMEOUT_SECONDS` is now passed on every call (regression test added).

## Security considerations

* Key stored only in `.env` (gitignored); settings hold it as `SecretStr`; `describe()`, status and diagnostics
  report only "set"/"not set"; reports scanned for `hsk_`/`sk-ant-` (none).
* The Cloud key cannot be sent to the self-hosted server or any non-https host.
* Isolation remains structural (bank per customer); recall additionally drops any hit from another bank and links
  evidence only through our own `(bank_id, memory_id)` ledger for the requesting customer.
* Recommendation: use a dedicated Cloud organisation for this app with an expiring key. Bank-restricted keys do not
  fit dynamic per-customer banks unless banks are pre-created.
* The app itself still has no user authentication (unchanged; localhost only).

## Limitations

1. **Observation consistency is eventual:** after an edit or delete, a consolidated observation can briefly still
   state the old fact (the probe needed up to ~2 minutes in total). Observations are returned as `unlinked`
   evidence and cannot be traced to a record; M5 should label or exclude them when presenting evidence.
2. Credit balance and promotional terms cannot be read via API; cost is estimated from reported tokens.
3. Latency figures come from one run with 1–3 samples per operation.
4. Rate limits are undocumented and were not exercised.
5. Re-syncing interactions (e.g. customer rename) costs ≈ $0.02 per interaction on Cloud.
6. Self-hosted LLM mode (with an Anthropic key) remains unverified; Cloud now covers the LLM-backed path.
